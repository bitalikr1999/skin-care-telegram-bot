# ТЗ: SkinLog — Telegram-бот

## 1. Призначення

Бот для ведення щоденника: користувач фіксує щоденні активності (їжа, побут, довкілля), симптоми (стан шкіри, самопочуття) і загальну оцінку стану шкіри. Мета — згодом проаналізувати накопичені дані та знайти кореляції між активностями і станом шкіри. Увесь ввід — тільки кнопками, без вільного тексту.

## 2. Роль користувача

Одна роль: **Користувач**. Будь-яка людина, що написала боту `/start`, отримує власний ізольований простір даних, прив'язаний до її Telegram `chat_id`. Користувачі між собою ніяк не перетинаються: кожен бачить і редагує тільки свої записи. Бот публічний — доступ не обмежується списком дозволених ID, реєстрація/авторизація не потрібна, `/start` і є реєстрацією.

## 3. Технічний стек

- Мова: **TypeScript**
- Рантайм: **Node.js**
- Telegram Bot API: бібліотека **Telegraf**
- Зберігання даних: **SQLite** (файлова БД, без окремого сервера)
- Запуск: long polling (без webhook, без зовнішнього HTTP-сервера)
- Без cron/планувальника, без будь-яких пуш-нагадувань — бот пасивний, реагує тільки на дії користувача

## 4. Довідники (preset-списки)

Дані вводяться виключно вибором зі заданих списків. Вільний текстовий ввід від користувача для даних щоденника не передбачений в жодному сценарії. Списки **не** редагуються через інтерфейс бота.

Кожен пункт довідника має стабільний `key` (snake_case) і `label` (текст для UI). У записах користувача зберігається лише `key`. Джерело довідників — seed-дані в коді; при старті додаток сідить їх у SQLite **один раз** (якщо таблиця порожня). Далі бот читає довідники з БД.

### 4.3 Оцінка стану шкіри

Ціле число від **1 до 10** (1 — дуже погано, 10 — відмінно). Одне значення на день, не мультивибір.

## 5. Дата запису

Усі дії за замовчуванням застосовуються до **поточної дати** (сьогодні). Вибору довільної дати заднім числом у MVP немає. Повторний вибір активності/симптому в межах того самого дня — перемикач (toggle): перший клік додає, повторний клік прибирає.

## 6. Головне меню

Показується по команді `/start` та `/menu`, а також як кнопка "Назад" з будь-якого екрана. Складається з незалежних одна від одної дій — не покроковий сценарій, користувач сам обирає, що робити, в будь-якому порядку і будь-яку кількість разів за день:

1. **➕ Додати активності**
2. **🩺 Додати самопочуття**
3. **📊 Стан шкіри (1–10)**
4. **📋 Сьогоднішній запис** — перегляд поточного стану дня
5. **📈 Статистика**

## 7. Сценарії

### 7.1 Додати активності
Відкриває inline-клавіатуру з усіма активностями, згрупованими за категоріями (заголовок категорії — некликабельний роздільник). Уже вибрані сьогодні пункти позначені ✅. Клік по пункту — toggle (додати/прибрати), клавіатура одразу оновлюється (`editMessageReplyMarkup`, без пересилання нового повідомлення). Можна вибрати від 0 до необмеженої кількості пунктів. Кнопка "Готово" повертає в головне меню.

### 7.2 Додати самопочуття
Те саме, що 7.1, але для довідника симптомів. Повністю незалежний сценарій від активностей — не пов'язаний з ним послідовністю кроків.

### 7.3 Стан шкіри (1–10)
Клавіатура з числами 1–10. Клік записує/перезаписує оцінку за сьогодні (не toggle, а заміна значення). Поточне вибране значення візуально виділене.

### 7.4 Сьогоднішній запис
Текстове зведення поточного дня: оцінка, список вибраних активностей, список вибраних симптомів. Без редагування прямо тут — тільки перегляд, редагування через пункти 7.1–7.3.

### 7.5 Статистика
Для кожної активності, у якої є щонайменше 2 дні "з нею" і 2 дні "без неї" серед днів з проставленою оцінкою: середня оцінка стану шкіри в дні з активністю vs без неї, різниця. Якщо оцінених днів менше 3 загалом — повідомлення "замало даних" замість таблиці. Топ-3 активності з найбільшим негативним зв'язком і топ-3 з найбільшим позитивним. Обов'язкова примітка в тексті відповіді: це кореляція, не причинно-наслідковий доказ.

### 7.6 Експорт CSV
Генерує CSV (`date,rating,activities,symptoms`, у комірках — **label** через `; `, не key) з усіх записів користувача і надсилає файлом у чат.

## 8. Модель даних

SQLite. Ключ ізоляції користувачів у записах — `chat_id`. Довідники глобальні (спільні для всіх).

```
activities(
  key PRIMARY KEY,
  label,
  category_key,
  category_label
)
symptoms(
  key PRIMARY KEY,
  label,
  category_key,
  category_label
)
ratings(chat_id, date, rating)
  PRIMARY KEY(chat_id, date)
activity_records(chat_id, date, activity_key)
  PRIMARY KEY(chat_id, date, activity_key)
  FOREIGN KEY(activity_key) REFERENCES activities(key)
symptom_records(chat_id, date, symptom_key)
  PRIMARY KEY(chat_id, date, symptom_key)
  FOREIGN KEY(symptom_key) REFERENCES symptoms(key)
```

Seed: **лише через CLI** (`MOD=cli` → команда `seed`). Schema + catalogs; якщо таблиці вже не порожні — seed не перезаписує. При старті бота seed **не** запускається.

Шлях до файлу БД: env `SQLITE_PATH` (default `./data/skin-diary.sqlite`). Адаптер: `infra/db-light` (SQLite via knex + better-sqlite3); паралельна реалізація під інший рушій — окремий модуль (напр. `db-pg`).

Запуск:
```
pnpm seed          # MOD=cli seed
pnpm start:bot     # MOD=bot (requires BOT_TOKEN)
```

## 11. Шари Telegram

- `infra/telegraf` — Telegraf client, long polling, рендер `IBotView`
- `presentation/telegram-api` — команди/колбеки → application → `IBotView`
- Presentation не залежить від Telegraf

Callback protocol: `nav:*`, `act:toggle:<key>`, `sym:toggle:<key>`, `rat:set:<n>`, `done:*`.

## 9. Явно поза межами MVP

- Вільний текстовий ввід нотаток
- Дата заднім числом / календар
- Фото
- Нагадування, cron, будь-які фонові/заплановані завдання
- Множинні ролі, адмінка, статистика по всіх користувачах разом
- ML / передбачення — тільки описова статистика (середні + різниця)

## 10. Критерій готовності

Будь-який користувач Telegram пише `/start`, за кілька натискань кнопок фіксує день, у будь-який момент бачить `/статистика` і може вивантажити `/export CSV`. Дані користувачів не перетинаються між собою.
